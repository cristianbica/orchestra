# Routing and Gate Contract

This guide is the authoritative route, gate, ownership, and completion contract. Conductor selects exactly one executable target row before execution. `guided` is a wrapper modifier, not a second selected route. Role, workflow, operation, playbook, and adapter instructions may add procedure or stricter safety checks, but must not weaken or replace the selected target row.

## Route rules

- A route's `None` plan entry is intentional. Do not create or request a plan merely because the work is non-trivial.
- An approved plan constrains only the route and scope it names. Operation or playbook invocation approval cannot approve a `change` implementation.
- If route eligibility stops holding, stop before out-of-route writes and promote to the matrix row whose gates cover the work.
- `guided` changes interaction cadence only. Conductor records it as a modifier while the target row remains the sole selected route; it cannot add, remove, or satisfy target-route approval.
- Validator returns review status `approve` or `needs changes`; Conductor owns route terminal state. `approve` permits the row's successful terminal state once other evidence is complete. `needs changes` maps to `blocked` while remediation is possible, or `failed` when that row allows failure and the run is closed.
- Only Forger may combine specialist phases, and only after explicit user opt-in. It temporarily assumes Planner ownership and plan/report writes, Builder ownership and approved product/source writes, then Validator ownership and allowed docs/memory or operation writes. It never delegates, crosses phase permissions, or bypasses the approval stop.

## Shortcut recognition

Shortcuts classify intent only and then rejoin normal route intake, gates, ownership, validation, and terminal handling above.

- Match case-insensitively after leading ASCII whitespace. An alias matches only when it is the entire remaining message or begins the message and its next character is `:` or ASCII whitespace (`space`, `tab`, `CR`, `LF`, `FF`, or `VT`). Choose the longest match; ask only if equally long matches map to different targets.
- Command aliases: `/bootstrap`, `/refresh-context`, `/change`, `/feature`, `/bug`, `/refactor`, `/document`, `/investigate`, `/trivial-change`, `/guided`, `/create-overlays`, `/define-playbook`, and `/run-playbook`.
- Legacy phrase aliases use the same boundary grammar: `bootstrap`, `bootstrap this`, `refresh context`, `change`, `implement feature`, `fix bug`, `refactor`, `document`, `investigate`, `trivial change`, `guided`, `create overlay`, `create overlays`, `define playbook`, `create playbook`, and `run playbook`.
- Reject incidental substrings and token continuations such as `/changefoo`; otherwise use semantic routing when no alias matches.
